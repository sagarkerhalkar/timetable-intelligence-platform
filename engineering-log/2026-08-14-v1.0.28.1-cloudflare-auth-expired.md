## Safety / rollback state

- The new Worker code was **not deployed** because `wrangler whoami` failed before the deploy step.
- The installer stopped API 3550 only after local tests had passed.
- After the Cloudflare authentication failure, the installer restored the previous API source and restarted API 3550.
- Production database rows were not migrated, deleted, or replaced.
- Web port 3500 and protected dev port 3457 were not stopped.

## Recovery action

Re-authenticate Wrangler interactively on the Windows server, then rerun the same v1.0.28.1 package. Preferred interactive command:

```powershell
npx.cmd --yes wrangler@latest login
```

Complete the browser authorization in the same Cloudflare account that owns Worker `q`, then verify:

```powershell

```

Only after `whoami` succeeds should `RUN_NEXTTOPPERS_QR_FAST_SCAN_V1_0_28_1_NOW.cmd` be rerun.

Do not create or store a Cloudflare API token in the public repository. If API-token authentication is ever used, keep the secret outside GitHub and out of logs.
