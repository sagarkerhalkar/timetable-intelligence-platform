### FAIL/RISK CAUGHT BEFORE FINAL PACKAGE — wrong web-test invocation

The first installer draft used the project `npm run test` command. The recovered `package.json` defines that command as `vitest run --coverage`. Earlier v1.0.15.2 release history already proved that project-wide coverage thresholds can trigger a release rollback even when functional regression tests pass.

Root cause: the installer draft reused the package test script instead of the established functional release-gate rule.

Fix: the installer now invokes the local `node_modules\.bin\vitest.cmd run` directly, so all functional Vitest tests remain blocking while coverage thresholds remain a separate quality goal. TypeScript and full Next.js build remain blocking.

Result: correction applied before the final package was published.

### FAIL/RISK CAUGHT BEFORE FINAL PACKAGE — acceptance gate initially too weak

The first v1.0.25 installer draft stopped at QR page smoke checks after build/restart. That did not satisfy the locked acceptance requirement for existing-module runtime checks plus QR template/bulk/per-QR analytics behavior.

Fix: the final installer additionally checks Dashboard, Timetable, Sheet Updates and Test Monitor APIs, then creates temporary tracked QR template/bulk campaigns, verifies PNG generation, scans QR A once, proves QR A analytics=1 while QR B=0, deletes the template and proves the existing QR survives detached, and finally cleans up temporary QR records.

Result: stronger runtime acceptance gate included in final package.

### FAIL/RISK CAUGHT BEFORE FINAL PACKAGE — PowerShell variable-colon interpolation

A static audit found double-quoted strings with variable names immediately followed by `:` (for example `$Port:` / `$Url:`). Windows PowerShell can parse these as an invalid scoped-variable reference.

Fix: changed those occurrences to braced interpolation such as `${Port}:`, `${Url}:`, and `${codeId}:`. A follow-up colon-after-variable audit and balanced delimiter/string/comment structure audit passed.

### PASS — deterministic package reproduction

`release-source/v1.0.25/build-package.py` builds the acceptance ZIP directly from committed source. Two clean builds were compared byte-for-byte and produced the same SHA-256.
