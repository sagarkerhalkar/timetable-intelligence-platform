# 2026-08-14 — v1.0.29.4 background-push failure and v1.0.29.5 Cron-pull fix

## User-observed Windows result

v1.0.29.4 failed with:

`NOT ACCEPTED: API could not populate the Cloudflare QR edge route store within 20 seconds.`

The same run reported a successful Cloudflare Worker rollback and restarted the previous API source on port 3550. The production database was not migrated or deleted.

## Root cause

The installer had already completed an explicit protected seed of the current QR routes into Workers KV before restarting API 3550. After that successful seed, it unnecessarily required a second mechanism — a local FastAPI background push thread — to report `last_ok=true` within 20 seconds.

That local push-thread health gate was not required to prove the fast scan path because the KV store had already been seeded. It became a fragile acceptance dependency and caused repeated rollback even though the intended edge architecture had progressed further.

## v1.0.29.5 architecture

Normal QR scan remains:

`phone -> q.nexttoppers.workers.dev -> Workers KV -> tiny tracking page -> destination`

Initial installation:

1. Verify Wrangler auth/account and exact Worker build.
2. Create or reuse `nexttoppers_qr_edge` KV namespace.
3. Deploy Worker with KV binding and secret.
4. Explicitly seed all current QR routes into KV before API restart.
5. Restart only API 3550.
6. Verify DB integrity, foreign keys and unchanged schema fingerprint.
7. Verify protected Cloudflare -> API -> KV pull.
8. Verify a real sample QR response has `x-ntqr-source: kv`.

Continuous QR route synchronization is now Cloudflare-initiated:

- Worker Cron Trigger: every minute (`* * * * *`).
- Worker fetches protected `/backend/api/v1/qr-fast/edge-export` using the existing sync secret.
- Backend returns current QR routes plus per-route SHA-256 fingerprints.
- Worker compares fingerprints against a single KV manifest.
- Only changed QR keys are written; deleted slugs are removed.
- Manifest/index keys update only when the route set changes.
- The old API->Worker background push thread is disabled by default and is no longer an acceptance requirement.

This keeps user scan latency independent of the local server/Tunnel while retaining automatic destination/lifecycle updates.

## Cloudflare free-plan limits considered

As of 2026-08-14, official Cloudflare documentation lists Workers Free at 100,000 requests/day, KV Free at 100,000 reads/day and 1,000 writes/day, with up to 5 Cron Triggers per account. The one-minute Cron uses one origin pull and one manifest read per run; route keys are written only when QR data changes.

This package is for current proof/acceptance workload and does not claim the future 10,000,000-scan commercial target is supported by the Free plan.
