# 2026-08-14 — v1.0.29.3 KV duplicate-reuse failure and v1.0.29.4 fix

## Real Windows result

**Result:** FAIL / safe rejection.

Observed Cloudflare/Wrangler error:

```text
A KV namespace with the title "nexttoppers_qr_edge" already exists.
```

The installer then reported NOT ACCEPTED and restored source/runtime. Production SQLite was not migrated or deleted. Web port 3500 and protected dev port 3457 remain outside this change.

## Root cause

The `nexttoppers_qr_edge` namespace already existed from an earlier edge-KV attempt and was intentionally preserved for reuse. v1.0.29.3 did call `wrangler kv namespace list`, but its reuse parser expected a narrow JSON shape and failed to recover the existing namespace ID from the actual Wrangler output. It therefore incorrectly attempted `wrangler kv namespace create nexttoppers_qr_edge`, and Cloudflare correctly rejected the duplicate title.

This is an installer namespace-discovery/reuse bug, not a database problem and not evidence of KV corruption.

## v1.0.29.4 correction

`Ensure-KvBinding` is made idempotent and resilient:

- Reuse an existing valid local `QR_EDGE` binding when present.
- Otherwise run `wrangler kv namespace list --config wrangler.jsonc`.
- Parse historical JSON-array output.
- Accept both `title` and `name` fields.
- Recover a 32-hex namespace ID from human-readable output around the exact `nexttoppers_qr_edge` title.
- Add object-style regex recovery as another fallback.
- Create a namespace only when discovery finds no reusable namespace.
- If create still returns `already exists`, automatically re-list and reuse instead of aborting.
- Preserve an existing KV namespace on failed acceptance.

Cloudflare account pinning and exact Worker build/version propagation verification from v1.0.29.3 remain in place. Worker marker advances to `x-ntqr-fast: 5` and build ID `v1.0.29.4-account-pinned`.
