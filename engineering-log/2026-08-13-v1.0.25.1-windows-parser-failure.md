# 2026-08-13 - v1.0.25 Windows Parser Failure -> v1.0.25.1

## User-visible failure

After a long development session, the user ran the delivered v1.0.25 Windows package and immediately received PowerShell parser errors. This is a release-process failure: the package should not have been delivered without a Windows-PowerShell parser gate.

Observed primary error:

- `INSTALL_V1_0_25.ps1:243 char:98`
- `Unexpected token 'shared' in expression or statement.`

Cascade errors included:

- missing argument errors around `paginateItems(...)` contract strings;
- illegal ampersand errors on URLs containing query parameters.

Result: **FAIL - v1.0.25 not accepted.**

## Root cause

The installer contained one UTF-8 em dash in a PowerShell double-quoted marker string. The file had no UTF-8 BOM. Windows PowerShell 5.1 decoded it through the legacy code page, producing mojibake that included a smart quote. PowerShell recognizes smart quotes as quote characters, so the marker string ended early and the rest of the file produced cascade parse diagnostics.

The comma and ampersand diagnostics were therefore consequences of the original encoding/parser break, not separate TypeScript/URL logic defects.

## Important safety finding

This was a parse-time failure. The installer did not execute. Therefore the failed v1.0.25 attempt did not run the payload apply step from this script.

## Fix - v1.0.25.1

1. Replaced the typographic em dash with ASCII `-`.
2. Made the complete installer ASCII-only for Windows PowerShell 5.1 compatibility.
3. Added `PRECHECK_V1_0_25_1.ps1` which uses Windows PowerShell's own parser on the complete installer before any application action.
4. Precheck rejects any non-ASCII installer character.
5. Added payload file size + SHA-256 verification before backup/apply.
6. Kept the entire v1.0.25 QR UX payload unchanged.
7. Kept port 3457 protected.

## Process lesson - mandatory

For every future Windows PowerShell release:

- run a PowerShell parser gate before installer execution;
- use ASCII-only installer source unless a BOM/encoding contract is explicitly verified on Windows PowerShell 5.1;
- do not treat static delimiter/quote heuristics as equivalent to the real PowerShell parser;
- deliver code/package first, then documentation in the same development turn;
- record FAIL -> root cause -> fix -> PASS in GitHub before handoff.
