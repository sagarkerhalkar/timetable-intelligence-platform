# 2026-08-14 — v1.0.29.1 live DB count guard correction

## Windows acceptance result for v1.0.29

**Result:** FAIL / NOT ACCEPTED

**Exact first acceptance failure:**

`NOT ACCEPTED: Core DB counts changed during API source/runtime switch. Refusing acceptance.`

Tail evidence also showed the failed-run Cloudflare KV namespace was removed successfully and the previous API source/runtime was restarted. The installer reported that the production DB was not migrated/deleted.

## Root cause

v1.0.29 compared all live production table row counts before and after the API restart and required exact equality. That safety gate is invalid for a running production app because legitimate activity can change counts while the installer is executing, including QR scans, Sheet Updates/change records, Test Monitor records, and timetable/source synchronization.

This was a **false safety rejection**, not evidence of database corruption.

## v1.0.29.1 fix

The strict live-row-count equality gate is removed. Counts remain diagnostic only.

Database acceptance now requires:

1. `PRAGMA integrity_check` returns `ok`.
2. `PRAGMA foreign_key_check` returns zero violations.
3. A SHA-256 schema fingerprint remains unchanged before/after the runtime switch. The fingerprint is computed from sorted non-internal `sqlite_master` objects: object type, name, table name, and SQL.
4. The installer still performs no production DB migration/delete/replace operation.

The Cloudflare Workers KV fast-scan architecture from v1.0.29 is otherwise unchanged.
