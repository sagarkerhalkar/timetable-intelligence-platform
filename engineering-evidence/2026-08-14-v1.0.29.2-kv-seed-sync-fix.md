# 2026-08-14 — NextToppers QR Edge KV v1.0.29.2

## Real Windows failure

`NOT ACCEPTED: API could not populate the Cloudflare QR edge route store within 45 seconds.`

The failed-run KV namespace was deleted successfully by the v1.0.29.1 rollback path. Source/runtime rollback was attempted and the production DB was not migrated/deleted.

## Root cause / design weakness

v1.0.29.1 depended on the restarted FastAPI background thread to perform the *initial* API -> Worker -> KV route population. Acceptance waited 45 seconds for `edge-sync-status.last_ok=true`. If that initial background sync did not complete, KV remained empty and the installer rolled back even though Worker deployment and DB integrity could be healthy.

The initial seed should not depend on an asynchronous startup event.

## v1.0.29.2 correction

- Deploy Worker code, QR_EDGE binding and `NEXTTOPPERS_EDGE_SYNC_SECRET` atomically using Wrangler `deploy --secrets-file`.
- Add authenticated Worker `__ntqr_admin/status` verification for both KV binding and secret before API restart.
- Explicitly seed all current QR routes into Worker KV from the authoritative service DB before API restart.
- Add lazy-start protection for the FastAPI edge-sync thread in addition to startup registration, so health/status/resolve/confirm can ensure the sync worker exists.
- Keep continuous background delta sync verification after restart.
- Keep DB acceptance based on SQLite integrity, foreign-key check and unchanged schema fingerprint; live row counts remain informational.
- Do not delete/recreate the KV namespace on a later acceptance failure; retain it for safe reuse.
- Keep web 3500 untouched and protected dev port 3457 untouched.
